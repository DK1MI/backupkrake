Plausibility check (after every backup)

Compares each new snapshot with the previous successful backup of the host. A backup that “succeeds” but is much smaller than usual, e.g. because a disk on the client didn't mount or a container volume came up empty, is marked as a warning and always sends a notification. An empty snapshot is flagged too.

Content check against the client

Compares the latest snapshot of a host with the client, reading every file on both sides (rsync --dry-run --checksum, nothing is written). Normal backups only look at size and modification time, so they never notice a file whose content changed silently, e.g. bit rot on the backup disk or the client. Such files fail the check. Files that changed normally since the backup are only counted. Takes about as long as a full backup; start it for a single host with Verify against client on the host page. {% if v.content_check_enabled and next_content %}Next run {{ next_content|dt }}.{% endif %}
