Client setup

Backupkrake connects to each client as root over SSH and pulls the files with rsync. Clients need only rsync (3.2.4 or newer includes rrsync) and the server's key.

1. Install rsync on the client

# Debian / Ubuntu
apt install rsync
# Fedora / RHEL
dnf install rsync
# Arch
pacman -S rsync
# Alpine
apk add rsync rrsync python3

2. Authorise the server's key

Recommended: read-only. Add this line to /root/.ssh/authorized_keys on the client:

{{ restricted }}

The key can then only read files via rsync: no shell and no writes. If rrsync isn't on the PATH, use its full path, e.g. /usr/share/doc/rsync/scripts/rrsync on older systems (it may need to be unpacked and made executable).

Unrestricted (needed for pre/post commands such as database dumps):

{{ pubkey }}

One-liner to run on the client as root (read-only variant):

mkdir -p /root/.ssh && chmod 700 /root/.ssh && echo '{{ restricted }}' >> /root/.ssh/authorized_keys && chmod 600 /root/.ssh/authorized_keys

Optional: allow restores from the web UI

Restores use a second key that can only write, so the backup key stays read-only. Add this line as well on every host you want to restore to:

{{ restore_line }}

Unrestricted variant: {{ restore_pubkey }}. By default, restores go to a staging directory on the client ({{ staging }}/…); overwriting the original files is an explicit choice.

3. Allow key-based root login

In /etc/ssh/sshd_config on the client:

PermitRootLogin prohibit-password

Reload sshd afterwards (systemctl reload ssh or sshd). This permits key logins only, never passwords.

4. Add the host and test

Add the host, then use Test connection. The server learns the client's host key on first contact (trust on first use) and rejects it if it changes later.

Restoring

  • Back to the client: browse a snapshot, pick a file or folder and choose Restore…. Run a preview (dry run) first, then restore into a staging directory, the original location or any other folder, on the same or a different host. This needs the restore key above.
  • Download: browse a snapshot and download a file, or a folder as .tar.gz.
  • Directly from the server's disk: snapshots are plain directories in {{ data_dir }}/hosts/<host>/<snapshot>/. From the Docker host, copy back with rsync, e.g.
    rsync -aHAX --numeric-ids {{ data_dir }}/hosts/web1/latest/etc/nginx/ root@web1:/etc/nginx/
  • After losing the server: restore from the offsite restic repository with any restic client and the repository password.
